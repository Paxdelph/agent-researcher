# Контекст: маркетплейс (тестовый кейс)

Общий долгоживущий фон компании/продукта для всех рисерчей в папке `researches/`.
Brief конкретной задачи — в UI / brief рисерча.

## Компания

- Условный маркетплейс товаров повседневного спроса (e-com).
- Монетизация: комиссия с заказов + реклама селлеров.
- Основная аудитория: RU / CIS, mixed new + returning.

## Продукт

- Витрина + корзина + чекаут + оплата; web и нативные iOS/Android.
- Ключевые сущности: `user`, `session`, `cart`, `order` / `purchase`.
- Главная коммерческая воронка: `cart_view → checkout_start → payment_start → purchase`.

## Метрики и определения

- Cart→purchase обычно смотрят на уровне пользователя (первая попытка в окне), не «сырой» event rate.
- New vs returning: по `registration_date` / `prior_purchase_count`, не по «первому событию за день».
- Timezone логов: UTC; продуктовые дашборды часто в Europe/Moscow — при сверке учитывать.

## Данные и нюансы

- События воронки в product analytics / events-таблице; пользователи — в dim.users.
- На mobile недавно редизайн чекаута (только приложения; web без этого релиза) — см. текущий brief.
- `session_id` не всегда стабилен на web; для чувствительных метрик лучше опираться на `user_id` + правила окна.
- Боты/тест-аккаунты иногда попадают в events — при наличии флага лучше фильтровать.

## Чего обычно не делаем

- Не выдаём pre/post релиза за чистый A/B без holdout.
- Не мешаем cross-device в один user journey без явной identity-склейки.
